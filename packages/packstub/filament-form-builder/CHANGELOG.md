# Changelog

All notable changes to `packstub/filament-form-builder` are documented here.

## Unreleased — forked in-repo (hrs)

Vendored into `packages/packstub/filament-form-builder` as a local Composer path package so the app can carry permanent, uncommitted-upstream customizations without `composer update` ever reverting them.

### Added

- **Bilingual EN/AR content**: form name/description/submit label/success message (via `Spatie\Translatable`) and every field's label/placeholder/hint/choice labels (stored as `{en, ar}`, resolved with `App\Support\Localized`), edited with `App\Filament\Support\TranslatableInput` — the same pattern the app's CMS module uses.
- **File upload field type** (`Types\FileField`): accepted extensions and max size configurable per field in the builder; stores to a plain filesystem disk (`config('packstub-form-builder.uploads')`) from either the plain Blade POST or the Livewire renderer.
- **Brand styling**: `resources/css/form-builder.css` retinted to the site's warm palette and fonts; RTL-safe logical properties; the hosted page layout now loads the site's own stylesheet and sets `dir` from the locale.

- **Extension points for the host app**: `SubmissionReceived` can now steer what the visitor sees next (`redirectTo()`, `$message`, `$extra` merged into the JSON response, carried by `SubmissionResult`); `FormBuilder::registerFormTab()` adds a tab to the form editor; `FormBuilder::closedWhen()` closes a form for an app-specific reason; `FormBuilder::beforeForm()` renders markup above the fields in both the Blade and Livewire renderers. The app uses them to turn submissions of a form linked to a service into (paid) orders.
- **`FormBuilder::registerResourcePage()` and `FormBuilder::registerRecordAction()`** let the host app add a page of its own to the Forms resource (merged into `FormResource::getPages()`) and an action to every form (a row action of the forms table and a header action of the form editor). The app uses them for its per-form "Insights" page.
- **Submissions page**: a form's submissions moved from a relation manager under the editor to a page of their own (`Pages\ManageSubmissions`, `/forms/{record}/submissions`, open to whoever may view the form), and every form now has tabs at the top (`FormResource::getRecordSubNavigation()`): the editor, its submissions with the unread count, then any page the host app registered. Clicking a form in the list (or its submission counts, or the new "Submissions" row action) opens its submissions; the editor is one tab away. The table, slide-over and CSV are unchanged.
- **`FormBuilder::registerSubmissionActions()`** lets the host app add actions to the submissions page's menus (`export`, `record`, `bulk`); the page groups them with its own: an "Export" button (CSV first), a ⋮ menu per row (view / read state, the app's, delete) and the bulk menu. The app adds a PDF per language: all as filtered, the selected ones, one submission. The forms list's row actions are grouped into one ⋮ menu as well.
- **`FormBuilder::holdNotificationsWhen()`** keeps the "new submission" email back for a form (the host app holds it for an unpaid order and sends its own once it is paid).
- **Private file uploads**: uploads go to a private disk (`uploads.disk`, default `local`) and are reached through a signed download route (`form-files/{token}`) that also checks the `viewAny` gate on the form model, always served as an attachment and only inside the uploads directory. Earlier uploads on `uploads.legacy_disks` (`public`) are still served, and `php artisan form-builder:move-uploads-private` moves them.
- **Default extension deny-list**: a file field with no `accepted_types` allow-list of its own now still rejects server-executable/script extensions (`uploads.blocked_extensions`: `.php`, `.phtml`, `.exe`, `.sh`, ...), on both the plain Blade path (`FileField::rules()`) and the Livewire path (`FileUpload::rules()`), so an unconfigured field never silently accepts any file type.
- **Nationality field type** (`Types\NationalityField`): a searchable dropdown sourced from the app's public `Country` list (`nationality_en`/`nationality_ar`) instead of builder-entered choices — a Filament `Select` with `->searchable()` on the Livewire renderer. Added `FieldType::fixedChoices()`, a hook a type can use to supply its own value => label list instead of the field's `choices` option; `Field::choices()` consults it first.
- **`initCombobox` in `form-builder.js`**: the plain Blade renderer's base markup for a "nationality" field is an ordinary `<select>` (works with no JS, keyboard type-ahead included); the enhancement script (only present when `frontend.enhance` is on) upgrades it into a mobile-first searchable combobox — a text input that filters the options live, backed by a results panel that always opens downward and scrolls internally (`max-height:min(60vh,320px)`) instead of the browser's own select/datalist popup, which on a ~200-item list can flip upward and run off the top of the screen. The `<select>` stays the real, constrained form control (visually hidden once enhanced); the visible text can only ever be set to one of its option labels, so there is no way to submit a suggestion the visitor kept typing past (e.g. "Omani" -> "Omanisdjfs").
- **Radio buttons with details field type** (`Types\ConditionalRadioField`, id `conditional_radio`): radio buttons plus a follow-up text box (short or long) that only appears for the answers chosen in "Show the details box for" (e.g. "Did you travel last year?" No / Yes → "Where to?"). One field, one key: the value is stored as `{answer, details}` and printed as "Yes — Italy"; details typed and then left behind by switching to a non-revealing answer are dropped. The plain renderer shows and hides the box with CSS `:has()` alone, and the enhancement script (`initConditional`) toggles its `required`/`disabled`; the Livewire renderer is a `Group` with a live `Radio` and a conditionally visible input. Added the generic `FieldType::nestedRules()`/`nestedAttributes()` hooks (rules and message names for parts of a structured value, merged by `Form::validationRules()`/`validationAttributes()`), `FormState::error()` now also returns an error on such a part (`key.answer`), and `HasChoices::choicesRepeater()` can make choice values live so another setting can list them.

- **Conditional fields ("Show this field only when …")**: any field but a hidden one can carry one rule, `condition: {field, operator, value | choice}`, on an input field placed before it (not a hidden or file field); operators `is`, `is_not`, `filled` ("is answered"; "is ticked" for a tick box), `empty`. `Support\FieldConditions` is the judge: `Submitter::validate()` works out the visible fields from the input (in field order; a field hidden by its rule counts as unanswered for the fields that depend on it), validates only those (`Form::validationRules($only)`) and stores the others as `null`, whatever was sent. The Blade renderer carries each rule in `data-fb-show-when` and the enhancement script (`initRules`) shows/hides and disables the field live (without the script every field shows and the server ignores the extra answers); the Livewire renderer makes the source fields live and the dependent ones `visible()` by the same rules; the JSON definition exposes `condition` per field. The editor has a "Show this field only when" section per block (offering only earlier fields, their choices as a list, "Shown when …" summary, a "Conditional" header badge), and refuses to save a rule whose field is no longer before it (moved, deleted or renamed).
- **"Start from a template"** on a new form (`Support\FormTemplates`, `CreateForm::templateAction()`): Contact us, Service application (name, phone and email as a paid service needs), Booking request, Registration and Feedback (which uses a conditional field), every label filled in each configured language from the `templates`/`template_fields`/`template_choices` strings; replaces the fields and names the form when it has no name yet. Not offered on an existing form.
- **Editor language switch** (`Filament\EditorLanguages`): "All | EN | عربي" above the editor; every bilingual input of the form editor (`EditorLanguages::grid()`, used instead of `TranslatableInput::grid()`) follows it through Filament's client-side visibility (`visibleJs`), so a hidden language is never dropped from the state or on save, and the shown one takes the full width. Remembered per browser; a failed save (`form-validation-error`) switches back to all languages so no error stays out of sight.

### Changed

- `HasChoices` choices editor moved from a flat `KeyValue` to a `Repeater` of `{value, label: {en, ar}}` rows to support bilingual choice labels.
- **Form editor UX**: the form's name, slug, Active switch and description moved out of the Settings tab into a "General" section above the tabs (open on create, folded on edit), so a new form's name is asked first instead of failing as "required" on a tab nobody opened. A field block now shows only its label, Required, Width and the type's essential settings (choices, file types and size, heading level...); help text, placeholder, default value, key, extra validation rules and the plain input types' length/min/max/rows settings fold under a collapsed "More options" section (`FieldType::hasAdvancedSettingsOnly()`). The "Add field" menu is ordered by group (basic, contact, choices, other, layout: `FieldType::group()`, `FieldBlocks::GROUPS`) and shows a one-line description under each type (`FieldType::description()`, `type_descriptions.*` strings). A choice's English label comes first and fills its value when the value is blank (`HasChoices::choiceValue()`; an existing value is never changed, since stored answers refer to it). A file field's maximum size is a list in MB (still stored in KB; a custom size saved earlier stays on offer, `FileField::maxSizeOptions()`).

- **Form editor, second pass**:
  - **Preview** (header action on create and edit, `Concerns\HasPreviewAction`): a slide-over showing the form as it stands in the editor, unsaved changes included, drawn by the Blade renderer in the hosted page's layout, one tab per language and a desktop/phone width switch. The editor's state is parked in the cache for 30 minutes for the admin who asked (`Support\FormPreview`) and loaded by a sandboxed iframe (no `allow-forms`, so nothing can be sent) from `form-preview/{token}?locale=` (`PreviewFormController`; `?locale=`, not `?lang=`, so the admin's own language is not switched). The preview is always open, even for an inactive form or one outside its dates.
  - **Badges on a field's header** (`FieldBlocks::itemLabel()`): Required, Half width, and "AR missing" for each language with no label yet, so a folded form can be checked without opening every block.
  - **Typed default value** (`FieldType::defaultInput()`): a list of the field's choices (select, radio, radio with details; a default saved earlier that is no longer a choice stays on offer), the nationality list, a date picker, a number, an email or web address input.
  - **"Paste a list"** on the choices editor (`HasChoices::withPastedChoices()`): one choice per line, "English | عربي" or a tab between them, values made from the English label, existing values skipped.
  - **Settings**: "Redirect after submit" must be a full web address or a path starting with `/`; the success message says it is unused while a redirect is set; a warning when submissions are neither stored nor emailed; the opening/closing times show their time zone; "Require a logged-in user" says which accounts count (the default guard: staff, not phone-signed-in customers).

### Fixed

- The form slug, field keys, and the required name/label/choice/details label always come from the **English** text, never `TranslatableInput::defaultLocale()` (which reads `APP_LOCALE` and differs between servers: on an Arabic default the slug and keys came out empty or transliterated). A key left blank is also filled from the English label on save and in the duplicate-key check (`Field::keyLabel()`), not from the admin's current language.

## 1.0.0 — 2026-09-09

### Added

- **Forms resource**: build forms in the panel with a block per field type (text, email, phone, URL, number, long text, dropdown, radio buttons, checkbox, checkbox list, date, hidden, heading, paragraph), each with label, key, placeholder, help text, default, required, width and extra Laravel rules; settings for the submit button, success message, redirect, notification emails, storing submissions, an availability window, login requirement and spam protection; an Embed tab with copyable snippets.
- **Submissions**: stored with the values keyed by field key plus a snapshot of the labels, the page they came from, the channel, IP and user agent (both optional); a relation manager with a details slide-over, read / unread state, filters, bulk actions and a CSV export without extra packages; an unread badge on the navigation item.
- **Three renderers** on one submission pipeline: the `<x-form-builder::form>` Blade component (plain HTML, session-less friendly, optional in-place fetch submission), the `<livewire:form-builder>` component (Filament fields, in-place validation) and a JSON API (`GET /forms/{slug}/definition`, `POST /forms/{slug}` with `Accept: application/json`); a hosted page per form.
- **Spam protection** without a captcha: a honeypot, a time trap (encrypted token issued with the form) and a per-IP rate limit; dropped submissions fire `SpamDetected`.
- **Extending**: custom field types (`FieldType`), submission sinks (`SubmissionSink`) for CRMs and webhooks, the `SubmissionReceived` event, `FormBuilder::submit()` from code, swappable models and table names, CSS variables for theming.
